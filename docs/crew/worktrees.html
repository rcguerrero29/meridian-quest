What the git change buys you

Same crew, same tests, same merge button. The only thing that changes is how many of them can be working at once without stepping on each other. Nothing here changes how you play or how you merge.

One repo, one folder — today

Today: one checkout, one branch at a time

A folder on disk can only be on one branch. Everyone shares that folder.

The jam. Two people, one desk. The second one waits — not for a decision, just for the desk.

With worktrees: one repo, several desks

A worktree is an extra folder on disk pointing at the SAME repo, checked out to its own branch. Same history, same remote, same rules.

1Each agent gets its own folder.../wt-rosa-131, ../wt-beto-140, ../wt-nacho-doors.
2All three start at the same time.Nobody switches anybody's branch, because nobody shares a folder.
No jam. The desk stops being the bottleneck. The only bottleneck left is you, on purpose.
3Three PRs land together.CI runs all three in parallel. Each is still one branch, one ticket.
4You merge them in whatever order you like.If two touched the same file, the second one rebases and re-runs. The tests catch it, not you.

What it does not change

Stays exactly the sameWhy that matters
One branch per part, one PR per partYou can still read a PR in one sitting.
CI green before you see itNothing red ever reaches your merge button.
You merge. Nothing else merges.The irreversible step is still yours, alone.
The public game only changes for the public game's sakeThe town never leaks into Meridian.
Your laptop copy of mainThe town you play from is untouched by any of this.

The cost, honestly

What it costsHow bad
Disk: one working folder per active agentSmall — the history is shared, only the files are copied.
Two agents editing the same fileReal. Second one rebases; the four suites decide. Beto's rule: one ticket per area, not just per ticket.
More PRs open at onceReal, and it is the actual limit — not the machines. Three or four open is comfortable to read; ten is not.

That last row is the honest answer to "what is our limit in agents": it is not the tooling, it is how many PRs you want to read in one evening. Three concurrent is the number I would start with, and it is a number you can raise later by changing nothing but your mind.
